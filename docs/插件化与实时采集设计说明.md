# TrendHub 插件化与实时采集设计说明

> 版本：v1.0（设计稿，**未落地任何代码改动**）
> 适用范围：将 TrendHub 从"静态种子数据新闻站"改造为"可被其他项目调用的 AI 新闻采集与知识库插件"
> 前置结论：当前代码库**不存在**任何采集、调度、入库能力；AI 相关仅为占位残留。本文档给出决策完备的实施方案。

### 0.1 缓存层已确认的 3 个缺陷（直接决定"实时"能否成立）

**缺陷 A：TTL 从未生效。** `backend/config/cache_conf.py` L40：

```python
await redis_client.set(key, value, expire)   # ← 第三个位置参数是 nx，不是过期时间
```

`redis-py` 的 `set(name, value, nx=None, xx=None, ...)` 签名中第三位是 `nx`。传入 `7200` 被判真，等价于 `SET ... NX`，即"不存在才写、且**永不过期**"。因此 `news_cache.py` 里注释声明的"分类 7200 / 列表 600 / 详情 1800"整套过期策略实际不存在。

**缺陷 B：缓存命中返回字符串而非数组。** 写入时 `json.dumps`（L39），读取时 `get_cache_list_dict`（L27-32）直接 `return await redis_client.get(key)`，缺 `json.loads`。链路后果：`crud/news_cache.get_categories` L10-12 命中后原样返回该字符串 → `routers/news.py` L20-24 塞进 `data` → 前端 `/api/news/categories` 拿到的是 `"[{...}]"` 字符串，不是数组。

**缺陷 C：列表/详情缓存为半成品。** `crud/news_cache.py` L23-34 整段被注释，`cache/news_cache.py` L19-26 的更新/删除方法同样被注释——即当前**没有任何缓存主动失效能力**，这会在采集链路上暴露为新新闻不可见。

> 叠加效应：A 让 TTL 失效、C 让主动失效缺位，两者叠加 = 新闻入库后**永远刷不出来**。故 P0 必须先修，否则 P1 的采集做了也看不见。

### 1.2 分层原则

1. **core 不感知 HTTP**：不 import `fastapi`、不读 `Request`、不依赖任何路由对象。MCP 与 HTTP 是同一内核的两个薄壳。
2. **配置显式注入**：`Settings` 由入口构造并传入 `create_app(settings)` / `NewsPipeline(settings)`。禁止模块级 `os.getenv` + `raise`。
3. **两个插件化死结必须在 P0 解开**（否则无法被其他 Python 项目复用）：
   - `main.py` L6 顶层 `load_dotenv(...)` 会污染宿主进程环境变量；
   - `config/db_conf.py` L5-8 在 **import 时刻** 读 env 并 `raise ValueError`，同时 L11 建立全局 engine 单例 → 外部项目 `import` 即报错或抢占连接池。
4. **导入方式约束**：当前为扁平绝对导入（`from crud import news`、`from models.base import Base`）。改为可安装包时必须整体切换为相对导入或包前缀导入，影响面见 P3。

### 2.1 `news` 表增列

全部新增列**可空或带默认值**，种子数据与现有前端零影响。

```sql
-- 迁移：data/migrations/001_ingest_kb.sql
ALTER TABLE `news`
  -- 采集溯源
  ADD COLUMN `source`       VARCHAR(50)  NULL COMMENT '来源标识：jiqizhixin/qbitai/arxiv_cs_ai...',

  ADD INDEX        `idx_news_fetched_at`  (`fetched_at` DESC);

```

补充约束说明：

- **`image NOT NULL` 与 RSS 现实冲突**：RSS 条目经常无缩略图。两种处理，推荐前者：
  - (a) `ALTER TABLE news MODIFY image VARCHAR(255) NULL;` —— 需前端 `NewsList.vue`/`NewsDetail.vue` 对空图兜底；
  - (b) 采集侧落 `https://picsum.photos/seed/{id}/200/200` 占位，表结构不动。
- **`category_id` FK `ON DELETE RESTRICT`**：分类不可随意删改，采集数据统一挂靠新增的 AI 分类。
- **ngram 注意事项**：`ngram_token_size` 默认 2（改需重建索引并重启）；查询用 `MATCH(...) AGAINST(... IN BOOLEAN MODE)`；单字查询在 ngram=2 下召不回，`search` 接口需对 ≤2 字查询降级为 `LIKE`。
- **字段长度对齐**：`title VARCHAR(255)` / `description VARCHAR(500)` 为硬上限，采集侧必须截断（`normalize.py` 负责），否则 MySQL 严格模式直接报 1406。

### 3.1 采集实现要点

```python
# core/sources/rss.py 的正确姿势
async with httpx.AsyncClient(timeout=15.0, headers={"User-Agent": UA}) as client:
    resp = await client.get(feed_url, headers=cond_headers)   # ETag / If-Modified-Since
    if resp.status_code == 304:
        return SourceSkip(reason="not_modified")
    parsed = feedparser.parse(resp.content)                    # ← 传 bytes，不传 url
```

1. **不要用 `feedparser.parse(url)`**：`feedparser` 是同步阻塞库，直接传 URL 会在事件循环里做同步网络 IO，卡死整个 worker。正确做法是 `httpx` 异步取字节 + `feedparser.parse(bytes)` 纯 CPU 解析。
2. **并发与礼貌**：`asyncio.Semaphore(4)` 限制同时在途请求数；轮次内加 `random.uniform(0, 30)` 秒抖动，避免多副本同时打上游；UA 明确标注项目名与联系方式。
3. **每源故障隔离**：每源独立 `try/except`，单源异常只记 `ingest_state.last_error`，不中断整批。
4. **条件请求**：`etag` / `last_modified` 落库复用；`304` **不计入失败次数**（它是成功）。
5. **正文策略**：本期不做正文抓取（`trafilatura` 留到 P4）。`description` 取 `entry.summary`，`content` 优先 `entry.content[0].value`（或 `content:encoded`），无则复用 `summary` 并置 `raw_meta.body_extracted=false` 以便后续回补。
6. **时区归一**：RSS 时间戳混用 GMT / RFC822 / ISO8601，统一经 `feedparser._parse_date` → `datetime` → 转本地时区后**存 naive datetime**（`publish_time` 列是 `DATETIME`，无时区），并在 `raw_meta` 保留原始串。
7. **HTML 清洗**：`html.unescape` + 去标签（保留纯文本），再按列长度截断；`title` 若含换行需折叠空白。
8. **分类映射**：`source` → `category_id` 的映射表放 `Settings`，默认全部挂 AI(9)，`arxiv_*` 挂 科技前沿(10)（若决策项 2 通过）。
9. **`views` 字段**：采集数据初始 `views=0`，`update_views` 逻辑不变。

### 3.2 去重策略（双层 + 幂等）

```
第 1 层 批内去重    set(content_hash) 过滤同一轮 feed 内部重复条目
第 2 层 跨源去重    url_hash     唯一键 —— 拦转载/镜像（URL 归一化后同址）
        跨时间去重  content_hash 唯一键 —— 拦标题+日期同、URL 带跟踪参数的变体
```

**URL 归一化规则**（`dedupe.normalize_url`）：scheme 统一 `https` → host 转小写 → 去除 `utm_*`/`spm`/`ref`/`fbclid`/`gclid` 等跟踪参数 → 去 fragment → 去尾部多余 `/` → 参数按 key 排序 → `md5`。

**content_hash 规则**：`sha256( normalize_space(title).lower() + "|" + publish_time.date().isoformat() )`。用日期而非精确时间戳，是因为同一新闻在不同 feed 中发布时间常差几分钟。

**写入必须幂等**：

```sql
INSERT INTO news (...) VALUES (...)
ON DUPLICATE KEY UPDATE
    updated_at = CURRENT_TIMESTAMP,        -- 不改 views、不改 title，保证幂等
    raw_meta   = VALUES(raw_meta);
-- 依赖 MySQL 对多唯一键的处理：任一 UK 冲突即走 UPDATE
```

> 注意：`ON DUPLICATE KEY UPDATE` 无法区分是撞了 `content_hash` 还是 `url_hash`。若需要"同址更新正文"与"转载丢弃"的差异化行为，改为先 `SELECT ... WHERE url_hash=? OR content_hash=?` 预检再分支处理（`find_by_hash` 提供），代价是每条目多一次查询。本期采用预检方案，因为转载降级比正文更新更常见。

### 3.3 退避策略

| 场景 | 行为 |
| --- | --- |
| 网络/解析失败 | `fail_count += 1`，`last_status='failed'`，写 `last_error`（截断 500 字） |
| 下次执行间隔 | `base_interval * 2 ** min(fail_count, 3)`，即 ×2/×4/×8，**上限封顶 2 小时** |
| 连续失败 ≥ 4 | `last_status='backing_off'`，HTTP `/api/ingest/status` 标黄，超 24h 未成功标红 |
| HTTP 429 / 503 | 尊重 `Retry-After` 响应头，取其值覆盖公式计算结果 |
| HTTP 304 | 视为成功，`fail_count` 归零，本轮无新增 |
| 成功 | `fail_count = 0`，`last_status='ok'`，`last_success_at = now` |
| 单请求超时 | 15 s（`httpx.Timeout`） |
| 整轮预算 | 60 s，超时轮转下一批源，未完成源下轮补 |
| 多副本并发采集 | `SELECT GET_LOCK('trendhub_ingest', 0)`，取不到锁直接退出；**不引入 Redis 分布式锁** |
| 手动触发 | `force=true` 时绕过退避与水位线，全量重拉（仍走去重，不会重复入库） |

### 3.4 "实时"程度分档

| 档 | 机制 | 延迟 | 建议 |
| --- | --- | --- | --- |
| 1 | `POST /api/ingest/run` 手动/外部 cron 触发 | 取决于调用方 | 必做，是调试与兜底通道 |
| 2 | 进程内 `AsyncIOScheduler` 周期轮转 | 分钟级（RSS 上游本身延迟 10-30 min） | **默认档**，再密的轮询对 RSS 无意义 |
| 3 | 高 sensitve 源短周期（`hn_ai` 60 s） | 秒-分钟级 | 可选，单源特例配在 `Settings` |

调度入口挂在 FastAPI `lifespan`，worker 与 API 同进程部署；`docker-compose` 场景可用独立 `command: python -m core.worker` 且以 `SCHEDULER_ENABLED=false` 关闭 API 进程内的调度，避免重复。

### 决策项 1：向量库选型（阻塞 `news_vector` 是否真正落地）

### 决策项 3：是否允许从 MySQL 换成 PostgreSQL

这是**架构级分叉点**，必须在 P1 前定，因为 `core/store` 层与 DDL 的写法直接依赖它。

| 选项 | 说明 |
| --- | --- |
| **A. 保持 MySQL 8** | 现有 `aiomysql`、`data/database.sql`、`.env` 连接串全部沿用；全文检索用 `ngram`；向量走决策项 1 的 A/B/D |
| **B. 换 PostgreSQL 16 + pgvector** | 一站解决结构化 + 全文（`to_tsvector` + `pg_trgm`）+ 向量（HNSW）；但需重写 `database.sql` 全部 DDL、`aiomysql`→`asyncpg`、`utf8`→`UTF8`、中文全文检索需额外分词扩展（`zhparser`/`pg_jieba`，**增加编译安装成本**） |
